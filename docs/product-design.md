# Campus Knowledge Hub 产品设计方案

## 产品定位

Campus Knowledge Hub 是一个面向高校课程资料管理和智能答疑场景的多角色 RAG 知识库平台。系统让教师维护课程资料，让学生基于可信资料进行 AI 问答，让管理员监管知识库质量、文档处理任务和平台运行状态。

本次升级采用“学生端偏 AI 产品，教师/管理员端偏教务后台”的信息设计：学生需要快速获得答案和来源，教师需要管理课程资料和观察学生问题，管理员需要关注平台治理和运行状态。

系统演示资料采用开放教育资源和本地课程资料混合方案。

## 信息架构

### 学生端

- 学生首页：我的课程知识库、最近提问、推荐资料、学业概览、待复习提醒。
- AI 问答工作台：左侧会话与课程筛选，中间对话，右侧引用来源、资料详情、推荐追问。
- 知识库探索：按课程浏览资料来源、文档状态、知识片段。
- 学业分析：成绩明细、学分统计、课程平均分对比、学业风险提示。

### 教师端

- 教师首页：课程知识库总览、今日学生提问、文档处理状态、高频问题。
- 知识库管理：按课程组织知识库，设置公开范围和资料来源。
- 文档中心：上传课程大纲、讲义、实验指导、复习资料，查看解析状态和失败原因。
- 问题分析：高频问题、未命中问题、被引用最多资料、问答质量反馈。

### 管理员端

- 运营仪表盘：用户数、今日提问量、知识库数量、文档任务、AI 调用状态。
- 用户管理：学生、教师、管理员账号管理。
- 知识库审核：公开知识库审核、低质量资料处理。
- 文档任务监控：处理中、失败、完成任务，支持重试。
- 系统设置：模型模式、缓存状态、队列状态、部署配置。

## 演示故事线

1. 教师李老师登录，维护《Java 程序设计与软件构造》知识库。
2. 教师查看资料来源：MIT OCW、OpenDSA、校内实验指导。
3. 学生张同学登录，选择 Java 知识库提问：“ArrayList 和 LinkedList 怎么选？”
4. AI 返回回答，并在右侧展示来源：OpenDSA 数据结构资料、校内 Java 复习讲义。
5. 学生继续追问：“如果频繁在中间插入元素呢？”
6. 系统基于上下文回答，并给出推荐追问。
7. 学生询问：“我的数据库成绩怎么样？”
8. 系统识别为学业查询，直接查询结构化成绩数据。
9. 管理员登录查看运营仪表盘，关注文档任务、问答量和服务状态。

## 页面风格

- 学生端：现代 AI 工作台，强调对话、引用来源、推荐追问和回答可信度。
- 教师端：课程资料管理后台，强调课程、文档、状态、筛选和批量管理。
- 管理员端：运营治理后台，强调指标、任务、服务健康和异常处理。
