# Campus Knowledge Hub — 面试演示脚本

**时间**：约 8–12 分钟
**准备**：确保 MySQL、Redis、RabbitMQ 已启动，后端和前端正常运行

---

## 第一幕：教师建设知识库（3 分钟）

### 1.1 登录
> 打开 http://localhost:5173 → 登录页

- 点击 `teacher` 标签快速填入，密码 `123456`，点击登录
- 说明：**"系统有三个角色：学生、教师、管理员，演示账号内置在数据库中"**

### 1.2 创建知识库
> 进入「知识库管理」→ 点击「创建知识库」

- 名称：`Java 课程复习知识库`
- 描述：`面向 Java 课程的期末复习资料库`
- 可见性：选择「公开」
- 点击保存

> 讲解：**"教师负责建设课程知识库，每个知识库有可见性控制：公开、私有或仅课程可见"**

### 1.3 上传资料
> 进入「文档中心」→ 选择「Java 课程复习知识库」→ 点击「上传文件」

- 选择一个 .txt 或 .md 文件上传
- （如果没有真实文件，可以用记事本创建一个包含 Java 知识点的 txt 文件）
- 上传后列表中出现一条记录，状态为 `PROCESSING`

> 讲解：**"上传后会保存文档元信息，并投递到 RabbitMQ 进行异步切分。上传接口不会长时间阻塞，用户可以看到处理进度"**

### 1.4 查看处理结果
> 等待几秒，刷新页面或重新进入文档中心

- 状态变为 `DONE`，显示 chunk 数量和 processed_at 时间
- 点击「查看片段」，弹出片段列表

> 讲解：**"文档被 TextChunker 按 ~400 字切分，每个片段通过 KeywordMatcher 提取关键词。这是后续 RAG 检索的基础"**

## 第二幕：学生基于资料提问（4 分钟）

### 2.1 切换学生登录
> 退出登录 → 点击 `student` 标签 → 登录

### 2.2 浏览知识库
> 进入「知识库浏览」

- 看到刚才教师创建的「Java 课程复习知识库」
- 显示文档数、片段数、所有者信息

### 2.3 AI 问答 — 有命中场景
> 进入「AI 问答」→ 选择「Java 课程复习知识库」

- 提问：`Java 集合框架怎么复习？`

> 讲解：**"系统通过 QuestionRouter 判断这是 RAG 类型问题，走 RagService 检索 TopK 相关片段，然后调用 PromptBuilder 构造 Prompt，交给 LlmClient 生成回答"**

展示回答区域，重点指：
1. **AI 回答** — 基于知识库资料生成的答案
2. **引用来源** — 文档标题、片段序号、关键词得分
3. **RAG 检索追踪** — LLM 模式、检索耗时、生成耗时、来源类型
4. **Prompt 预览** — 展开查看模型收到的完整 Prompt

> 讲解：**"答案不只是文字，还包括引用来源和检索得分，用户可以核查依据；Prompt 预览便于调试 RAG，面试时也能展示 Prompt 构造逻辑"**

### 2.4 无命中保护
- 切换到一个空知识库或无资料的场景，提问一个无关问题
- 返回：`当前知识库未找到相关内容`

> 讲解：**"这是 AI 应用可靠性的关键边界——当知识库没有相关资料时，系统不会让模型自由发挥编造答案，而是明确告知用户未找到内容"**

### 2.5 问答历史
> 进入「问答历史」

- 展示刚才的问答被保存到 chat_record
- 显示来源类型、LLM 模式、时间

## 第三幕：管理员监控系统（2 分钟）

### 3.1 切换管理员登录
> 退出 → 点击 `admin` 标签 → 登录

### 3.2 系统看板
> 进入「系统看板」

- 用户数：3（student/teacher/admin）
- 知识库数、文档数、问答次数

> 讲解：**"管理员可以看到全局数据，帮助了解系统使用情况"**

### 3.3 用户管理
> 进入「用户管理」

- 展示三个内置账号及其角色

### 3.4 系统设置
> 进入「系统设置」

- LLM 模式：mock（演示时默认 mock 模式，不依赖外部 API）
- MySQL/Redis/RabbitMQ 连接状态
- RabbitMQ 管理界面和 Swagger 文档链接

> 讲解：**"系统支持三种 LLM 模式：Mock（演示用）、DeepSeek Real（真实调用）、Spring AI。通过配置文件的 llm.mode 切换。Redis/RabbitMQ/MySQL 连接状态实时展示"**

## 面试问答预案

| 面试官可能的问题 | 推荐回答要点 |
|-----------------|-------------|
| 为什么做多角色？ | 学生消费知识、教师维护资料、管理员关注系统状态，真实校园产品的需求不同 |
| 文档处理为什么用 RabbitMQ？ | 上传不阻塞用户、异步切分、状态展示结果（PROCESSING→DONE/FAILED） |
| 为什么没上向量数据库？ | 先做关键词 TopK 保证可运行可解释，RagService 已保留检索层，后续可替换 |
| 为什么返回引用来源？ | 知识库问答需要可核查的依据，引用来源帮助判断答案可靠性 |
| 成绩类问题为什么不走大模型？ | 成绩是确定性的结构化数据，直接查 MySQL 防止模型编造 |
| Redis 缓存什么？ | 知识库列表、FAQ、会话上下文；设置 TTL，失败降级到 MySQL |
| Prompt 预览有什么用？ | 调试 RAG 时看模型收到的资料片段和约束，面试展示 Prompt 构造逻辑 |
| 为什么不做注册和复杂 RBAC？ | 周五演示版聚焦核心业务链路，注册/找回密码/组织架构不影响演示价值 |
