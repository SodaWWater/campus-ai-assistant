# Campus Knowledge Hub — 面试演示脚本

**时间**：约 10-14 分钟
**准备**：确保 MySQL 已启动，Docker（Redis + RabbitMQ）已运行，后端和前端正常运行

---

## 第一幕：教师建设知识库（4 分钟）

### 1.1 登录
> 打开 http://localhost:5173 → 登录页

- 点击快捷标签 `👨‍🏫 教师` 快速填入，密码 `123456`，点击登录
- 进入教师工作台，看到左侧菜单：工作台首页、知识库管理、文档中心、问题分析、问答预览

> 讲解：**"系统有三个角色——学生、教师、管理员，各有一套独立的菜单和功能页面。"**

### 1.2 创建知识库
> 点击「知识库管理」→ 点击「创建知识库」

- 名称：`Java 课程复习知识库`
- 描述：`面向 Java 课程的期末复习资料库，含集合、IO、多线程等核心知识点`
- 可见性：选择「公开」
- 点击保存

> 讲解：**"教师负责建设和维护课程知识库，每个知识库支持三种可见性：公开、私有、仅课程可见。"**

### 1.3 上传 PDF / Word 文档
> 点击「文档中心」→ 选择刚才创建的知识库 → 点击「上传文件」

- 选择一个 `.pdf` 或 `.docx` 文件上传（建议提前准备一份 Java 知识文档）
- 文件类型支持：TXT、Markdown、PDF、Word（docx/doc）
- 上传后列表中出现一条记录，状态为 `PROCESSING`，页面自动每 3 秒轮询刷新

> 讲解：**"系统使用 PDFBox 提取 PDF 文本、POI 提取 Word 文本。上传后仅保存文档元信息并投递 RabbitMQ，接口立即返回。Consumer 异步切分，前端轮询展示处理进度。"**

### 1.4 查看处理结果
> 等待片刻，状态自动更新

- 状态变为 `DONE`，显示 chunk 数量和 `processedAt` 时间
- 点击「查看片段」，弹出片段列表（chunkIndex、content 前 200 字、提取关键词）

> 讲解：**"Consumer 收到消息后执行 TextChunker（400 字滑动窗口）和 KeywordMatcher 关键词提取。如果处理失败，RetryInterceptor 会指数退避重试 3 次（1s→2s→4s），耗尽后路由到死信队列（DLQ）标记 FAILED。"**

### 1.5 继续上传（可选）
- 再上传一份 .txt 或 .md 文件，演示批量资料管理
- 可在教师工作台看到文档数量、处理中/失败统计

## 第二幕：学生多轮对话与学业查询（5 分钟）

### 2.1 切换学生登录
> 退出登录 → 点击快捷标签 `🧑‍🎓 学生` → 登录

### 2.2 学习首页
> 自动展示学生首页

- 知识库数量、问答次数、文档数量统计卡片
- 最近知识库列表
- 快速提问入口：`Java 集合框架有哪些核心接口？`、`多线程如何保证线程安全？` 等

### 2.3 知识库浏览
> 点击「知识库浏览」

- 看到刚才教师创建的「Java 课程复习知识库」
- 显示文档数、片段数、所有者信息

### 2.4 AI 问答 — 多轮对话
> 点击「AI 问答」进入对话式聊天界面

**第一轮：选择知识库 + 提问**

- 顶部知识库下拉框选择「Java 课程复习知识库」
- 输入：`Java 集合框架有哪些核心接口？`
- 点击发送（或回车）

> 讲解：**"输入问题后，系统自动创建对话（左侧出现对话标题），通过 JWT 识别用户身份，加载该对话的历史上下文。"**

- 展示 AI 回答内容
- 点击「📎 参考资料」折叠面板，展示匹配的文档片段（documentTitle + chunkIndex + score）

> 讲解：**"每个回答附带了引用来源——文档标题、片段序号和关键词匹配得分。这是 RAG 可解释性的关键，用户可以核查依据。"**

**第二轮：追问（多轮记忆）**

- 在同一个对话中继续输入：`第一个接口的具体实现类有哪些？`
- AI 能结合上一轮的上下文（"第一个接口"指 Collection），给出对应回答

> 讲解：**"系统通过 Redis 存储对话上下文（最近 10 轮），每次提问时注入历史到 Prompt 中，实现真正的多轮对话记忆。Redis 设置 24 小时 TTL，同时数据持久化在 MySQL。"**

**第三轮：新建对话切换**

- 点击左侧「＋ 新对话」
- 选择同一个知识库，提问一个不同方向的问题：`多线程如何保证线程安全？`
- 新对话拥有独立的上下文，不会混入旧对话的内容

> 讲解：**"每个对话独立维护上下文，用户可以同时开启多个学习话题，切换对话不影响各自的历史。"**

### 2.5 快速提问入口（细节展示）
> 回到学习首页 → 点击快速提问 `Java 集合框架有哪些核心接口？`

- 自动跳转到 AI 问答页面，输入框已预填问题
- 直接点击发送即可

> 讲解：**"首页快速提问通过路由参数传递，进入聊天页自动预填输入框，减少用户操作步骤。"**

### 2.6 学业成绩查询
> 点击「学业查询」

- 展示当前登录学生的信息卡片：姓名、学号、专业、年级
- 统计指标：平均分、总学分、课程数
- 成绩明细表格：课程名称、课程代码、学分、成绩、学期

> 讲解：**"学业查询自动通过 JWT 中的 userId 关联 student 表，学生无需手动输入学号。成绩数据从 MySQL 直接查询，不走大模型，保证数据精度。"**

### 3.3 用户管理 — 全量 CRUD
> 点击「用户管理」

**创建用户：**
- 点击「创建用户」

- 展示系统中所有文档（含上传者、文件类型、大小、状态）

> 讲解：**"系统支持三种 LLM 模式——Mock（演示用，不依赖外部 API）、Real（DeepSeek API）、Spring AI。通过 application.yml 的 llm.mode 一键切换。"**

## 面试问答预案

| 面试官可能的问题 | 推荐回答要点 |
|-----------------|-------------|
| 为什么做多角色？ | 真实校园产品中，学生消费知识、教师维护资料、管理员关注系统状态，三者的需求边界和权限隔离完全不同。 |
| 文档处理为什么用 RabbitMQ？ | 上传接口投递消息后立即返回，Consumer 异步切分。配置 RetryInterceptor 指数退避重试 3 次，耗尽后 RepublishMessageRecoverer 路由至死信队列（DLQ）标记 FAILED。Jackson JSON 序列化避免反序列化安全问题。 |
| 为什么没上向量数据库？ | 演示阶段用关键词 TopK 保证可运行和可解释（得分机制透明），RagService 已预留检索层抽象，后续可替换为向量检索。 |
| 对话记忆怎么实现的？ | Redis List 存储最近 10 轮 Q&A 对（24h TTL），每次提问注入 Prompt；同时 MySQL 持久化，Redis 不可用时自动回退查询。业界主流方案：热缓存 + 持久化双写。 |
| RAG 如何工作的？ | 关键词匹配检索 TopK 片段 → 获取文档标题 → 构造 Prompt（角色+历史+参考资料+问题） → 始终调用 LLM → 返回回答 + 引用来源。检索结果为参考资料而非唯一权威，LLM 可结合自身知识补充。 |
| 为什么返回引用来源？ | 知识库问答需要可核查依据，答案溯源提升可信度；面试展示 RAG 可解释性闭环。 |
| 成绩查询为什么不走大模型？ | 成绩是确定性结构化数据，直接查 MySQL 保证精度，防止模型编造分数。 |
| 学生表为什么需要同步？ | 管理员创建学生用户时，sys_user 和 student 表通过 user_id 关联；学业查询通过 JWT userId 自动识别学生，无需手动输入。 |
| Redis 缓存什么？ | 对话上下文（List, 24h TTL）、FAQ 缓存（String, 30min TTL）、知识库列表。均设 TTL，失败降级到 MySQL。 |
| 为什么用 DataInitializer？ | 启动时自动建表/加列/初始化演示账号和 BCrypt 密码，无需手动执行 SQL 脚本，降低演示部署成本。 |
| 为什么不加注册和复杂 RBAC？ | 演示聚焦核心业务链路（教师建库→学生提问→管理员监控），注册/找回密码/组织架构不影响演示价值。 |

## 演示前检查清单

- [ ] MySQL 服务已启动（端口 3306）
- [ ] Docker 已运行，Redis（端口 6379）和 RabbitMQ（端口 5572）已启动
- [ ] 后端编译通过：`mvn -q -DskipTests compile`
- [ ] 前端构建通过：`cd frontend && npm run build`
- [ ] 浏览器打开 http://localhost:5173，确认登录页正常显示
- [ ] 三个演示账号均可登录（student / teacher / admin）
- [ ] 准备 1-2 份测试文档（.txt / .md / .pdf / .docx）
- [ ] 若使用 real 模式，确认 DeepSeek API Key 已配置
